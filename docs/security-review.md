# Server security review

Scope: server authentication, REST/STOMP authorization, uploads, IDOR, presence
privacy, errors/logging, CORS/headers/actuator, and dependency hygiene. This is a
local source-and-test review for the single-node demo, not a production
penetration test or dependency advisory scan.

## Accepted risks

- Registration discloses `PHONE_EXISTS` to preserve the current registration UX; login remains enumeration-resistant and both endpoints are rate-limited.
- A revoked or reused refresh token revokes all active sessions for its account. Access JWTs already issued remain valid until their 15-minute expiry because there is no access-token denylist.
- The SimpleBroker, presence registry, and rate-limit state are single-process. This is not a multi-node deployment contract.
- The native STOMP client sends its short-lived access JWT in the CONNECT `Authorization` header. This avoids putting the bearer token in a URL, but it remains replayable if intercepted; public deployment must use TLS/WSS.
- Raw inbound WebSocket text messages use Spring's effective 16,640-byte per-session buffer minimum. Larger raw frames close at the transport layer without a STOMP error response; the STOMP decoder's separate assembled-message cap is 65,536 bytes.
- CORS and WebSocket origin patterns are permissive for the native demo. Public deployment needs TLS/WSS and explicit origins.
- Message and attachment contents are plaintext at rest; end-to-end encryption is outside this release.

## Cross-owner requests

- `docs/websocket-protocol.md` is owned by codex-docs. Please add under the transport section: “With the current defaults (Spring WebSocket 6.2.1, Tomcat 10.1.34), Spring raises the Tomcat text-message default (8,192 bytes) to an effective 16,640-byte per-session inbound limit. The STOMP decoder has a separate 65,536-byte assembled-message limit. A raw WebSocket text frame over 16,640 bytes is closed by the transport before STOMP can return `/user/queue/errors`; limits count bytes, not characters. Application payloads over 10,000 characters that remain within the transport limit return `VALIDATION_FAILED`.” Evidence: no project size override; Spring `StompSubProtocolHandler.afterSessionStarted` raises the session limit to 16,640.
- Consider removing user/conversation/message UUIDs from non-owned service logs. Current log statements do not include direct contact data, credentials, or content, but UUIDs remain correlatable identifiers.

## Verification limits

- Dependency patch/CVE status is unverified offline; no SCA report was generated.
- A fresh isolated schema needs `public` in the PostgreSQL search path for already-installed extension operator classes. The isolated schema is first, so migration tables and test data stay there; shared `public` business rows were not used.
- Round 2 `mvn -q verify` exited 0 on the isolated schema. Fresh reports written during the invocation contain 398 Surefire tests across 63 suites and 66 Failsafe tests across 12 suites, with 0 failures, errors, and skips. Eight older Surefire XML reports from 2026-11-05 were excluded by timestamp; four contain failures from earlier runs and were not part of this invocation.
- No physical-device, production, or external penetration test was performed.
